## Rigorous lower bounds (proved; both used below)
- LB1  Z*_SSP >= K* - 1            (Crama: >=K* distinct covering configs => >=K*-1 changes)
- LB2  Z*_SSP >= |U| - b           (each tool loaded >=1x; first <=b free; = da Silva M-C bound)
  => Z*_SSP >= max(K*-1, |U|-b).

## OP4 [THEOREM -- proved + verified]: Z*_SSP = min over ALL feasible groupings of GTSP cost
- Proof. (<=) every feasible grouping + GSP ordering + per-group config is an SSP schedule,
  so min over groupings >= Z*... reversed: it is an upper bound, hence >= Z*. (>=) given an
  optimal SSP schedule, assign each job to the (size-b) configuration that serves it; jobs

- Verified: 1306 instances (b=3 edge family m<=5 + 800 random mixed-size, b in {3,4}), 0 violations.

## ============ OP6 RESOLVED (fourth session) ============
## CLUSTER-AGGREGATED MTZ IS *NOT* EXACT (proved by counterexample)
- The cluster-MTZ constraint u_j' - u_j'' + n*a_{j'j''} <= n-1 is representable for a config
  path IFF (1) every ordered cluster pair has a_{j'j''}<=1 (cluster-simple) AND (2) the
  precedence digraph D={j'->j'' : a_{j'j''}=1} is ACYCLIC. Earlier search tested only (1).
- Condition (2) fails under JOB DOMINATION: if T_i subset T_j, any config covering j also
  covers i, so an arc between two such configs puts {i,j} on both ends -> edges j->i and i->j
  -> 2-cycle -> no valid u.
- Counterexample (b=3): jobs {1,4},{1,3,4},{1},{1,2,4}. Exact: Z*_SSP=1, min covering-path
  cost=1, but min cluster-MTZ-REPRESENTABLE cost=2. So OPT_MTZ=2 > 1 = Z*. Cluster-MTZ
  overestimates / excludes the optimum. (Verified by full brute force over covering paths.)
- Broadened corrected search: 19 counterexamples in ~7.9k mixed-size b=3/b=4 instances.
- CONSEQUENCE for column generation: do NOT use cluster-aggregated MTZ. Use either
  (a) per-CONFIGURATION MTZ u_C - u_{C'} + N x_{CC'} <= N-1 (standard, exact), or
  (b) lazy SEC/PCTSP cuts (Part II, exact). The BBC job-indexed MTZ (Part VIII) is fine.
